# Review 与修订协议

> 适用于 review、检查、先诊断再改、逐章修订和系统处理全部章节。
> 单次 Review 只做一次完整扫描；后续文字微调不重复启动全章诊断。

## 一、执行流程

1. **确定范围**：列出本次涉及的章节和已有版本，不扫描无关文件。
2. **结构化 Review**：逐章标记影响结论、数据、逻辑和口径的问题。
3. **补齐公开证据**：对可公开验证的数据进行检索；找不到时降低结论强度或标记待核查。
4. **定向修订**：按 `rewrite-execution-protocol.md` 执行问题和动作，不整章盲改。
5. **复核**：检查原问题关闭、数据未变口径、跨章一致性未破坏。
6. **输出**：Review 报告用于审阅；正式修订稿输出可直接进入文稿的连续正文。

同一版本的同一条问题只记录一次。用户只要求局部改写时，仅处理指定章节和受影响衔接。

## 二、Review 报告

```markdown
# 第X章 Review

## 结论
- 当前完成度：
- 是否需要补证据：
- 主要风险：

## 问题清单

| 位置 | 问题 | 类型 | 影响 | 修改动作 | 优先级 |
|---|---|---|---|---|---|
|  |  | 数据/逻辑/结构/文风 |  |  | P0/P1/P2 |

## 待补材料
- P0：

## 修订边界
- 本次会修改：
- 本次不修改：
```

问题应定位到段落、小节或数据项，并给出可执行动作。避免加强论证优化表达这类无法验收的泛评。

## 三、优先级

- **P0**：事实错误、无来源关键数字、因果不成立、与主档冲突、承诺超过证据。
- **P1**：论证缺失、结构颠倒、关键假设未说明、跨章口径不一致。
- **P2**：重复、衔接、措辞和格式问题。

P0 未解决时，不把材料标记为完成；涉及私有事实缺失时向用户提问。

## 四、修订与自检

修订时保留已验证的事实、数据和专有名词。新增内容必须能追溯到主档、research 或明确假设；不得为了提高完整度补造案例、合同、用户数据或成果。

完成后检查：

- [ ] 原 Review 问题已逐项关闭或有明确未决状态。
- [ ] 关键数字、术语和结论跨章一致。
- [ ] 没有引入新的事实、承诺或绝对化表述。
- [ ] 正式稿没有诊断词汇、meta 说明和提纲化残留。
- [ ] 文风符合 `tone-guide.md`，篇幅符合 `chapter-depth-guide.md`。

关于分析稿/成稿的差异，以 `long-form-writing.md` 为准；详细动作和 T1-T6 分类以 `rewrite-execution-protocol.md` 为准。
