# 定向改写执行协议

> 用于 `review-rewrite-protocol.md` 的第三步逐章修订。目标是把不能这样写落实为可执行的改写动作。
> 不在此重复完整文风规范和正文输出格式。

## 一、先诊断，再改写

通读目标章节，先标记问题类型和建议动作，再动笔。不要直接润色或整章无差别重写。

| 编号 | 病灶 | 识别信号 | 主要动作 |
|---|---|---|---|
| T1 | 政策罗列 | 堆政策名称，不说对本项目的含义 | 补判断、解释和项目落点 |
| T2 | 提纲扩写 | 大量分点、标签标题、并列措施 | 合并为承接式论证段 |
| T3 | 短句堆叠 | 一句一断，像 PPT 文案 | 合并语义单元，补逻辑连接 |
| T4 | 论证不足 | 结论跳跃，缺证据或机制解释 | 补证据、解释、限制条件 |
| T5 | 展示稿口吻 | meta 说明、宣传腔、致敬式表达 | 删除 meta，改为中性陈述 |
| T6 | 缺项目落点 | 通用分析不落到本项目 | 补目标、指标、节奏或资源配置影响 |

默认处理顺序：T5 → T2 → T1/T4/T6 → T3。

## 二、问题记录

每个实质问题使用一条记录，避免笼统写加强论证：

```markdown
- 位置：
- 原句：
- 类型：T1-T6
- 动作：删除/合并/改写为/补出/前置/补过渡
- 依据：对应协议条款
```

只记录会改变事实、逻辑、结构或结论强度的问题；标点和同义替换不单独建卡。

## 三、改写动作

| 目标 | 允许动作 | 要求 |
|---|---|---|
| 去展示腔 | 删除、改写为 | 删去面向评委的解释和过程播报 |
| 去提纲化 | 合并、整合、展开 | 分点内容按因果或递进关系连成段落 |
| 补论证 | 补出、增加 | 补证据、解释或反例，不补空话 |
| 补项目落点 | 收束、归结 | 说明对项目指标、路径或决策的实际影响 |
| 修结构 | 前置、后接、重排 | 保持事实不变，修正论证顺序 |
| 修衔接 | 增加承上句、增加过渡句 | 解决跳跃或重复，不添加机械连接词 |

改写时保留原文中已验证的数据、专有名词和事实。无法确认的数据改为保守表述、标记待核查或删除，不得补造。

## 四、段落验收

改写后的每个重要段落检查：

- [ ] 有明确判断，不是事实堆叠。
- [ ] 证据或来源足以支撑判断，措辞没有超过证据强度。
- [ ] 解释了证据与判断之间的关系。
- [ ] 说明了与本项目的关系，或明确说明这是背景信息。
- [ ] 没有 meta 说明、标签句、宣传腔和机械分点。
- [ ] 与主档、research 和其他章节的数据/术语一致。

次要事实或背景段不必强制五行齐全，但不得跳结论或重复前文。

## 五、执行流程

1. **诊断**：标记 T1-T6 和影响范围。
2. **排序**：先删除错误口吻和错误结构，再补事实与逻辑，最后处理衔接。
3. **改写**：逐问题执行，保留有价值事实。
4. **局部复核**：确认原问题已消失，且没有引入新数字或新承诺。
5. **成稿复核**：全章通读，检查结构、口径和与其他章节的衔接。
6. **输出**：正式稿直接输出正文；诊断记录只在用户要求时保留。

若问题来自缺少私有事实，应停下向用户确认；若来自公开证据不足，先 Research，找不到就降低结论强度。
