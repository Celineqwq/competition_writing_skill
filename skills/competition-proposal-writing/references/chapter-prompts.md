# 单章深写规范

> 用户要求写第 X 章 / 深入写某章时使用。章节结构以 `framework-generation.md` 为准，篇幅与维度以 `chapter-depth-guide.md` 为准。

## 写作前检查

1. 读取 `.project-config.md`，提取本章需要的项目事实。
2. 读取目标章节的结构、对应角色和写作规范。
3. 只列本章相关的缺失项：
   - 公开证据缺失：先 Research 或标待核查。
   - 私有事实缺失：向用户提问，不得推断。
4. 检查已有章节和 research，复用已确认的术语、数字与结论。

不需要在每次写作前重复回显整个主档；只回显会影响本章判断的关键字段和缺失项。

## 单章输出

### A. 正式章节

按框架输出连续正文。表格只用于必要的量化或对比，重要结论按证据强度措辞，未验证内容明确标记。

### B. 本章 PPT 提炼

```markdown
## 本章 PPT 提炼
- 页面标题：
- 核心结论：
- 三个要点：
  1.
  2.
  3.
- 图表建议：
```

仅当用户需要 PPT/路演时输出；普通章节写作不自动追加。

### C. 缺失证据清单

```markdown
## 缺失证据清单
- [ ] [缺什么] - 影响[哪个判断] - 获取方式[用户确认/公开检索/实验]
```

### D. 图表占位

需要图表时，在正文使用：

```markdown
图X-Y【待生成】：图名
```

具体规范见 `output-standard.md`。

## 缺失项处理

- **P0 私有事实**：团队履历、合同、用户数据、融资、技术秘密等，停止依赖该事实的段落并向用户提问。
- **P0 公开证据**：市场规模、政策、竞品等先检索；检索不到则标待核查并降低结论强度。
- **P1 增强材料**：案例、图片、补充访谈等可先标记，不阻塞正文。
- **AI 推断**：仅用于结构和待确认假设，必须标注，不能写成已确认事实。

## 写作风格

遵循 `tone-guide.md`：结论清楚、数字有来源、措辞与证据匹配、少用绝对化表述。正式章节输出后按 `strict-review.md` 做一次完整复核，不重复启动全章改写。
